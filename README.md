# zin
The Zinnen sentence-annotation interface: studio videos of signed sentences → time-aligned ELAN annotation.

## What it does
- `zinnen.html`: filterable table of every sentence with its videos, EAF/SRT status, mocap takes and Signbank glosses.
- `getZinnen.php`: the one big endpoint behind it, dispatching on `action` (`fetchSentences`, `fetchRow`, `saveSubtitlesAndEAFFiles`, `editZin`, `uploadEAF`/`downloadEAF`, `delete*`, `findGloss`/`findgvg`, `listMocapFiles`).
- Output per video: one `.eaf` plus one `.srt` per tier (Nederlands, Signbank ID glossen, Gebaar-voor-gebaar) in `eaf/zin/`, served at `/zin/eaf/zin/`.
- Side pages: `dashboard.html`, `addZinnen.html`, `webapp.html`, `zinnenVideoStatus.html`, `no_video_worklist.html`, `undelete_videos.html`, `action_stats.html`, `lemmaProcessingMonitor.html` (lemma API: `lemmaTable.MD`, `lemmaMCP.MD`).
- The editors (subBeta8, 3DAnn3) live in `signlab_annotation-editors`; `zinnen.html` links to `/annotation-editors/…`.

## Where it runs
- Production VPS: `<root>/zin`, `https://signcollect.nl/zin/`. Demo hosts: dev2 `/web/zin`, dev-1 `/srv/signcollect/web/zin`.
- `<root>` comes from `sc_paths.php` (vendored `signcollect-lib` resolver, falls back to `/web`).
- Cron (user `gomer`, not in any repo): `30 3 * * * php /web/zin/resync_video_count.php`.

## Status
Production (the annotators' daily tool).

## How to run / deploy
No build step: plain PHP/mysqli + static HTML/JS. Deployed by `signlab_signcollect-stack` (`repos.tsv`: `zin` → `main`, cloned/hard-reset into `<root>/zin`); see
https://github.com/Amsterdam-Humanities-Labs/signlab_signcollect-stack.
Optional side services (not needed to serve the app):
- `websocket-server.js`: Node timecode relay on port 8766, proxied at `/zin_wss` (`npm install`, `node websocket-server.js`).
- `iss_client/`: ISS segmentation client (`composer install` in `iss_client/`).

## Configuration
| file | what |
|---|---|
| `<root>/mysql_config.php` | DB credentials (`$servername`/`$username`/`$password`/`$database`), included as `../mysql_config.php`. Gitignored, no template. |
| `iss_client/config.php` | ISS client settings; gitignored, create per host. |
| `.env` | `WS_PORT` for `websocket-server.js`; template `.env.example`. |
| `eaf/`, `record3D/`, `backups/` | host-local content, gitignored; `eaf/zin/` must exist and be writable by the web user. |
| `cache/mocap_index.json` | generated by `mocapFiles.php` (600 s TTL). |

DB index the mocap filter relies on: `idx_mocap_filter ON matched_transcriptions(zOg, added, has_mocap, m_transcription(20))` (`migrations/`).

## Dependencies
- MySQL `admin_gebarenoverleg` (`sentences`, `matched_transcriptions`, `lemmaTable`, `mocap_files`, …).
- `signlab_annotation-editors` at `<root>/annotation-editors` (edit buttons 404 without it); `/userProtect.js` from the stack's `web_extra/`.
- `signlab_sCAPI` as the `api/` gitlink, aliased to `/api`. Known gap: there is no `.gitmodules`, so a clone leaves `api/` empty.
- Video: `<root>/gebarenoverleg_media/studioFilesMini/{raw,post}`, an rclone mount where `find` returns nothing (use `scandir`/`glob`).
- Signbank dump `<root>/signbank_data/glosses_transformed.json` (from `signlab_signCollect-v2`); `leffe.science.uva.nl:8043` is called by `getSenses.php`/`webapp.html`.
- WebSocket services: handshape `ws://localhost:9000`, sign-segmentation `ws://localhost:8765`, ISS `wss://signcollect.nl/ISS_Server/ws` (not on demo hosts).
